# トンマナ共有用デザインシートの制作指針

出力はLPを撮影した画像を貼るだけの一覧ではなく、実装されたデザインの見本帳にする。ユーザーが別の作業へ画像を添付するだけで、配色と印象が伝わることを目指す。

## 推奨配置

基準キャンバス：幅1600px、高さ2000px。上下左右64px程度の余白、ブロック間32px程度。必要な場合は高さを増やす。

1. 上部：案件名、用途、デザインを表す2〜3語、作成日。
2. 配色：主要色5〜8色。各色を十分な面積で見せ、役割名とHEX値を色面の下の明るい背景に表示する。暗色上に黒文字などを置かない。
3. 左側約820px：見出し・本文・価格の実例、CTA・カード・オファーの見本、余白・角丸の値。
4. 右側約570px：実際のスマートフォンLPのファーストビューと、代表セクションの切り抜き。画面幅375pxのキャプチャを適度に拡大して載せられる。
5. 下部：画像・別ページで守るルール、画像素材の確定状態、参照元。

スマートフォン画面を丸ごと細長く縮小しない。各キャプチャの対象をラベルで明記する。見本の数を増やすより、主要な色と部品を読める大きさで見せる。

## 実装の取得

- LPをローカルHTTPで表示し、幅375px程度で値と見た目を確認する。
- `getComputedStyle` で主要要素のcolor、backgroundColor、fontFamily、fontSize、fontWeight、lineHeight、borderRadius、borderWidth、paddingを取得する。
- 同じ色がメインとCTAを兼ねる場合、色面を無理に重複させず「メイン／CTA」と示してよい。
- CSS変数だけでなく、上書きされた実際の値も確認する。透過色を無理に不透明のHEXへ変換しない。必要ならRGBAと背景の組合せを併記する。
- 幅により異なる文字サイズは対象画面幅を記録する。フォントの指定名だけで、未インストールの書体が使われていると断定しない。
- UI部品はDOMのスクリーンショットか、取得した値を反映したHTMLで描く。別の美しいデザインへ勝手に置き換えない。

## 再利用用データ

`design-tokens.json` の構造例。値は実装から取得して埋め、仮の数値を納品しない。

```json
{
  "project": "案件名",
  "source": "../lp/index.html",
  "createdAt": "作成日",
  "viewport": {"width": 375},
  "colors": {},
  "typography": {},
  "components": {},
  "visualRules": [],
  "imagery": {"status": "未確定または使用中", "direction": "観察した方針"},
  "pending": []
}
```

## 検証と引き渡し

- PNGに日本語が正常に描画され、ラベル・HEX値・CTA文言が切れていない。
- 対象LPと画像の色・書体・ボタン形状が一致する。
- 写真が未確定の場合は、その旨が画像にも書かれている。
- シートHTMLの画像は相対参照とし、同梱assetsから表示できる。
- テスト出力や作業中の値を確定設定として残さない。
- 書き出し不能な環境では、画像完成と報告せず、保存したHTMLと不足する実行環境を伝える。
